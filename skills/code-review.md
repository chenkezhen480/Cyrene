# 代码审查规范

## 审查步骤

1. 理解代码变更的背景和目的
2. 检查安全漏洞（注入、XSS、权限绕过等）
3. 检查性能问题（N+1查询、内存泄漏、阻塞调用等）
4. 检查代码风格和可维护性
5. 使用 web_search 查阅相关最佳实践
6. 提交审查意见

## 审查标准

### 安全性
- 不放过任何 OWASP Top 10 漏洞
- 检查输入验证和输出编码
- 验证认证和授权逻辑
- 检查敏感数据处理（密码、token、密钥）

### 性能
- 关注时间复杂度和空间复杂度
- 检查数据库查询效率
- 识别潜在的阻塞操作
- 验证缓存策略

### 可读性
- 命名清晰、符合约定
- 逻辑简洁、避免嵌套过深
- 注释充分、解释"为什么"而非"是什么"
- 函数长度适中（建议<50行）

### 可维护性
- 遵循 DRY 原则
- 适当的错误处理
- 良好的模块化设计
- 易于测试的代码结构

## 输出格式

```
## 审查结果

### 严重问题
- [文件:行号] 问题描述

### 建议改进
- [文件:行号] 改进建议

### 优点
- 做得好的地方
```
