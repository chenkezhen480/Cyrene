## 已确认的公共接口缺陷

`AgentOrchestrator` 的简化 `run()` 重载传入空 CancellationToken，完整重载也将该参数标为可选。但协调器原样传入要求非空令牌的 `AgentRunContext`，因此请求在 ReAct 前失败。共享 `AgentRunCommand` 现在在请求生命周期开始时为缺省参数创建独立令牌；显式令牌保留同一实例和取消状态。同步、结构化、流式调用共用该命令，不削弱下层非空约束。

- RED：7 项会话/取消检查中，两项复现 `cancellationToken cannot be null`。
- GREEN：取消、会话、运行和实验控制共 13 项通过，0 失败/错误。
- 证据：[修复前](regressions/optional-cancellation/red/)、[修复后](regressions/optional-cancellation/green/)。
- 之前 HTTP 查询参数、路径转义、查询凭证覆盖、OpenAPI JSON 请求体和本地 Schema 引用的修复及 63 项回归证据仍保留在 [HTTP/OpenAPI 记录](regressions/http-openapi-body/)。

## Docker 恢复边界

恢复时 Docker Desktop 未运行。启动失败日志定位到临时 `Docker/run/dockerInference` socket，Windows 报无法访问该对象。这与 Docker 官方问题跟踪中的[同类启动失败报告](https://github.com/docker/desktop-feedback/issues/625)相符；没有据此认定本机存在磁盘损坏。

在确认两个目录只含零字节 socket reparse point、目录自身不是 reparse point 后，停止本次启动的失败 Docker 进程，将以下临时目录原位重命名保存，再启动 Docker：

- `%LOCALAPPDATA%/Docker/run` → `run.cyrene-experiment-20261013`
- `%LOCALAPPDATA%/docker-secrets-engine` → `docker-secrets-engine.cyrene-experiment-20261013`

没有删除原 socket，没有重置 Docker，没有更改持久化数据盘或数据库卷。Docker 已成功启动，恢复时没有运行的容器；仅启动本任务的隔离项目，并重新读取动态端口。当前 `20261013-controlled` 的 7 项服务全部健康；此前实验项目仅停止，存储和原始结果保留。
