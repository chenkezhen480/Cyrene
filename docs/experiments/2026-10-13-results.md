后续独立框架业务接入对照已完成，见 [Cyrene 与 Spring AI Alibaba 实测](2026-10-13-alibaba-results.md)。该轮为相同合成宿主的 11 题 × 3 次 × 2 框架，共 66 次；知识题不在该轮范围，勿与下方 48 次 Wiki 数据混算。

本轮完成 16 题 × 3 条件 × 1 次，共 48 个真实模型试验。业务日期固定为 2026-10-12，执行恢复于 2026-10-13。使用 `deepseek-flash`、temperature=0.7、thinking=off、`embedding-3`/1024 维、无重排；Jev 配置保留，由完整显式路由判断绕过，未测 Jev。

人工分数有两条调整，全部保留原始行和原规则分数：

- 原生循环的续约列表结果正确，完整遵守分页；额外解释 C103/C106 被排除，触发了过严的禁词规则，人工改为通过。
- Wiki 组的混合题正确创建两条待办、没有给冻结客户建单，但回答额外声称“已转交紫槐应急台V6”。工具和宿主状态没有转交证据，人工判定失败。这是完成声明的忠实性问题，不能把本轮描述成零幻觉或完美完成。

这说明小样本中 Wiki 在保持四道检索事实正确时减少了输入量，但不能据此证明普遍降低费用或提高效率。模型采样、查询改写、重试和 Provider 缓存都会影响耗时/用量；一次运行不能给出稳定收益或跨产品胜负结论。

## 独立核对与对照边界

- 48 个独立会话，48 个不同 trial，全部 `status=completed`；每次事务 reset 后的宿主初始状态完全一致。
- 输入/输出逐次 API 用量覆盖 48/48；缓存用量另列于分析 JSON。没有可核验价格/账单，未换算金额；摄取、Embedding 和基础设施总成本未包含在 LLM 对话 Token 中。
- 9 个分页样本均按每页 2/2/1 条、连续 nextCursor 读到 hasMore=false，结果编号集合精确匹配。
- 3 个幂等样本均至少有两次不同 callId 的相同有效请求，两次返回 T0004，最终只新增一条；无效参数产生的失败请求没有算作幂等成功证据。
- 跨负责人读取三组均真实调用 C201，并收到 HTTP 404；没有泄漏客户名。跨负责人更新三组均从自己的完整列表确认 T0003 不可见后拒绝写入，未实际发 PUT；本轮不能宣称已经实测 PUT 的越权拒绝。
- Wiki 两组共用模型、文档、当前修订、签名读取、可信范围和宿主工具；差异为是否先使用 Wiki 目录发现。限定 SOURCE_DOCUMENT、长期注入预算为零、禁用记忆写工具，防止条件间答案污染。
- Native 条件共享 Cyrene 工具、授权和原文检索，只比较循环编排。它不是独立 LangChain4j 产品，也没有证明哪个完整框架接入已有系统更省人工时间。OpenAPI 导入程序耗时 55 ms，不包含开发者学习、配置、审查与部署时间。

## 实验带来的修复

1. HTTP API 查询参数、路径转义和查询凭证覆盖正确；OpenAPI 本地 Schema 引用展开，JSON 请求体不再带错 `__body__` 外壳。63 项定向回归通过，保留修复前失败证据。
2. 公共简化 `run()` 的可选 CancellationToken 在共享命令生命周期处初始化，显式令牌身份和预取消状态保留。相关 13 项检查通过。
3. 实验入口按正常 HTTP Handler 注入可信凭证，并在 finally 恢复；凭证/路由/native 6 项检查通过。此前不公平试验已保留并标明无效。
4. ReAct 在调用 Tool/ToolGroup 前拒绝非法 JSON、非对象参数和 JSON 后的多余内容，返回同 callId 的明确失败，允许模型修正后继续；合法无参数 `{}` 不变。修复前两条路径分别错误执行 8 个非法参数请求，补充尾随内容后又复现 3 个漏过的请求；修复后 21 项 ReAct/流式/结构化检查通过。

**本轮性能数据采集于第 4 项修复前。修复后只做无外部模型的定向回归，未复测性能，也不宣称该修复后的性能收益。** 另有宿主、准备和统计脚本共 23 项 Python 检查通过；未跑全量发布验收、真实生产系统或管理 UI 验收。测量时尚未提交、推送，未修改版本号；后续介绍文档和 Git 交付不会改变本轮数据的采集时点。
