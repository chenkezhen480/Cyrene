# Cyrene 首轮实验记录

## 范围与判定

- 基于当前工作区 `0.6.6` / `5eecc54`，保留自主 ReAct 决策，不要求固定工具调用顺序。
- 本轮验证已有系统接入、业务状态正确性与 Wiki 的信息精度和用量差异。
- Jev 是集成能力，按用户要求取消独立速度/成本对照；两组保留同一配置。
- `wiki_on` 使用现有 Wiki 目录发现和原文读取；`wiki_off` 在实验适配器中直接检索相同原始文档片段。两组共用模型、Embedding、重排配置、权限、原文、初始业务状态和任务。
- 用受控宿主 API 和独立 MySQL/Milvus/Redis 容器运行。原有容器、数据库和 `.env` 不作变更。私密配置与临时数据库位于被 Git 忽略的 `.runtime/`。
- 任务完成以原始回答中的确定性事实和宿主数据库最终状态判定；同时保留工具记录、Trace、Token、耗时和失败原因。

## 执行计划

1. 实现有 OpenAPI、当前用户鉴权、游标分页、事务与版本检查的隔离宿主样例及状态断言。
2. 构建来自当前源码的 opt-in Java 实验入口，复用 AgentOrchestrator、HttpApiTool、知识摄取与签名读取。
3. 启动独立容器、复制用户当前模型配置并记录 SHA-256；密钥不进入实验结果。
4. 先运行少量知识与业务任务，检查对照组公平性及结果记录，再运行完整首轮任务集。
5. 根据失败样本处理实际缺陷，按需复跑相关任务，保留改进前后结果。
